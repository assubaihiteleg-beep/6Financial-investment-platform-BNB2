# نظام إدارة الوكلاء (المستخدمين) ونظام البحث والفلترة المتقدمة لقائمة المستفيدين

خطة تطوير متكاملة لتمكين الأدمن من إنشاء وإدارة حسابات "الوكلاء" (Agents) بصلاحيات مخصصة وحصص محددة للمستفيدين، مع عزل بيانات المستفيدين لكل وكيل وحماية الحقول الحساسة، بالإضافة إلى محرك بحث وفلترة احترافي وشامل لقائمة المستفيدين.

## مراجعة المستخدم والقرارات المؤكدة (User Review & Critical Decisions)

> [!IMPORTANT] تم تأكيد القرارات التالية بناءً على إجابات الأسئلة التوضيحية:
> - **طريقة تسجيل الدخول**: صفحة تسجيل دخول مشتركة وموحدة مع التعرف التلقائي على نوع الحساب (أدمن، وكيل، أو مستفيد).
> - **المسمى المعتمد**: "الوكلاء" (إدارة الوكلاء / الوكيل المسؤول).
> - **محرك البحث والفلترة في قائمة المستفيدين**: بحث فوري متعدد الحقول (الاسم، اسم المستخدم، رقم الهاتف، الآيبان) + فلاتر الحالة (نشط / معطل / مجمد) + فلاتر مراحل الرسوم (المرحلة 1، 2، 3، مخصصة، مسدد، غير مسدد، مسدد جزئياً) + فلتر الوكيل المسؤول + خيارات فرز متعددة (الأحدث، الأقدم، الأكثر أرباحاً، الأعلى رسوماً، التاريخ).

## 1. نظرة عامة والمفهوم الأساسي (Overview & Core Concept)

### الهدف والوظيفة:
1. **نظام الوكلاء (Agent Management)**:
   - الأدمن يمتلك قسماً مخصصاً في لوحة التحكم لإدارة الوكلاء: إنشاء وكيل جديد، تعديل، حذف، تجميد أو تعطيل.
   - تحديد حصة (Quota) قصوى لعدد المستفيدين المسموح للوكيل بإضافتهم (قابلة للزيادة في أي وقت من قبل الأدمن).
   - ربط مستفيدين حاليين بالوكيل، وأي مستفيد يضيفه الوكيل يُربط به تلقائياً ويُخصم من حصته.
   - **عزل البيانات الصارم**: الوكيل عند تسجيل دخوله لا يرى في النظام سوى المستفيدين المرتبطين به فقط.
   - **حماية الحقول الحساسة للمستفيد**: الوكيل ممنوع قطعياً من تعديل الحقول الخمسة التالية:
     1. اسم المستفيد الكامل (`name`).
     2. اسم صاحب الحساب البنكي (`account_holder`).
     3. اسم المستخدم (`username`).
     4. رقم الآيبان (`iban`).
     5. رابط تسجيل الدخول المخصص (`login_slug`).
   - بقية الحقول (مثل الأرباح، الرسوم، الهاتف، حالة الحساب) ومراحل الرسوم والبطاقات تتاح للوكيل فقط إذا منحه الأدمن الصلاحية المناسبة (`can_edit_beneficiaries`, `can_manage_phases`, `can_manage_financials`).
   - يمكن للأدمن إظهار كلمة المرور النصية للوكيل (`plain_password`) كما هو متبع مع المستفيدين.
   - يمكن للوكيل تغيير كلمة مروره من حسابه.

2. **محرك البحث والفلترة المتقدم (Advanced Beneficiaries Filter & Search)**:
   - شريط بحث ذكي وفوري يبحث في (الاسم، اسم المستخدم، الهاتف، الآيبان).
   - شريط كبسولات وفلاتر منسدلة أنيقة:
     - فلترة حسب حالة المستفيد: الكل، نشط، معطل، مجمد.
     - فلترة حسب الوكيل المسؤول (للأدمن لاختيار وكيل محدد أو المستفيدين غير المعينين).
     - فلترة حسب حالات الرسوم والمراحل (الرسوم غير مسددة، مسددة جزئياً، تم السداد).
     - فرز متقدم: الأحدث تسجيلاً، الأقدم، الأكثر أرباحاً، الأكثر رسوماً، الترتيب الأبجدي.
   - مؤشرات إحصائية سريعة أعلى الجدول تعكس نتائج الفلترة فورياً.

## 2. تجربة المستخدم والتصميم البصري (User Experience & Visual Design)

### الهوية البصرية والتصميم:
- متوافق تماماً مع نظام التصميم المعتمد للتطبيق المالي (درجات الكحلي الفاخر `#1a1f3c`، الأزرق الملكي `#2952e3`، مع ألوان الحالات: الزمردي `#16a34a` للنشط، الكهرماني `#d97706` للجزئي والمعلق، والأحمر `#ef4444` للمجمد).
- استخدام الخط العربي الأنيق `Cairo` مع أرقام جدولية موحدة `tabular-nums`.

### مسارات المستخدم الرئيسية (User Flows):
1. **مسار الأدمن - تبويب "إدارة الوكلاء"**:
   - زر بارز "+ إضافة وكيل جديد": يفتح نموذجاً شاملاً (اسم الوكيل، اسم المستخدم، كلمة المرور، الحصة المحددة للمستفيدين، وصلاحيات التعديل وإدارة المراحل).
   - بطاقات الوكلاء: عرض إحصائيات كل وكيل (عدد المستفيدين الحاليين / الحد الأقصى للحصة، الحالة، زر إظهار/نسخ كلمة المرور، أزرار التعديل والحذف والتجميد).
   - نافذة ربط المستفيدين: إمكانية اختيار مستفيدين من القائمة وتعيينهم للوكيل دفعة واحدة.
2. **مسار تسجيل الدخول الموحد (Universal Login)**:
   - نافذة الدخول تتعرف تلقائياً على نوع الحساب:
     - إذا كان الحساب أدمن -> يوجه إلى لوحة الأدمن الكاملة.
     - إذا كان وكيلاً -> يوجه إلى لوحة الوكيل المخصصة المعزولة.
     - إذا كان مستفيداً -> يوجه إلى لوحة المستفيد.
   - مع إمكانية التحقق الصارم من حالة الوكيل (إذا كان مجمداً أو معطلاً يتم إيقافه برسالة واضحة).
3. **مسار الوكيل داخل لوحة التحكم**:
   - يرى فقط قائمة المستفيدين المرتبطين به.
   - شريط تقدم يوضح استهلاك الحصة: (مثال: تم إضافة 3 من أصل 5 مستفيدين متاحين).
   - زر "إضافة مستفيد جديد" يتعطل تلقائياً عند استنفاد الحصة مع تنبيه للتواصل مع الأدمن لزيادتها.
   - عند فتح ملف مستفيد: تكون الحقول الحساسة (الاسم الكامل، صاحب الحساب، اسم المستخدم، الآيبان، الرابط) مغلقة للقراءة فقط (Read-only مع أيقونة قفل 🔒).
   - التحكم في المراحل والعمليات المالية يظهر فقط إذا كانت الصلاحية ممنوحة من الأدمن.
4. **مسار البحث والفلترة الاحترافية لقائمة المستفيدين**:
   - صندوق بحث مريح مع زر مسح سريع.
   - صف أزرار كبسولية (Chips) للتصفية السريعة مع عداد للنتائج الحالية.
   - منيو تصفية متقدم يفتح فلاتر الوكيل وتاريخ الإنشاء وحالات الدفع والمراحل.

## 4. مصفوفة الصلاحيات والحقول المحمية (Permissions & Security Matrix)

| الحقل / الإجراء | الأدمن (Admin) | الوكيل (Agent) |
| :--- | :--- | :--- |
| **إدارة الوكلاء والحصص** | مسموح بالكامل (إنشاء/تعديل/تجميد/حذف) | غير مسموح تماماً |
| **اسم المستفيد الكامل** | تعديل كامل | 🔒 مقفل للقراءة فقط |
| **اسم صاحب الحساب البنكي** | تعديل كامل | 🔒 مقفل للقراءة فقط |
| **اسم المستخدم (username)** | تعديل كامل | 🔒 مقفل للقراءة فقط |
| **الآيبان البنكي (IBAN)** | تعديل كامل | 🔒 مقفل للقراءة فقط |
| **رابط الدخول (login_slug)** | تعديل كامل | 🔒 مقفل للقراءة فقط |
| **إضافة مستفيد جديد** | بلا حدود | مسموح ضمن حدود الحصة (Quota) |
| **رؤية المستفيدين** | كافة المستفيدين في النظام | المستفيدين المرتبطين به فقط |
| **تعديل الهاتف/الأرباح/الحالة** | مسموح | مسموح فقط إذا فُعّلت `can_edit_beneficiaries` |
| **التحكم بالمراحل والبطاقات** | مسموح | مسموح فقط إذا فُعّلت `can_manage_phases` |
| **إجراء العمليات المالية والسداد** | مسموح | مسموح فقط إذا فُعّلت `can_manage_financials` |

## 5. خطوات التنفيذ (Implementation Steps)

1. **قاعدة البيانات (Database Layer)**:
   - إنشاء جدول `agents` في PostgreSQL عبر SQL DDL والـ ORM.
   - إضافة عمود `agent_id` في جدول `beneficiaries`.
   - تحديث نماذج Drizzle ORM وملفات الأنواع.

2. **الخلفية البرمجية (Backend Routes & Security)**:
   - إنشاء مسارات الوكلاء في `/api/agents` (جلب، إضافة، تعديل، حذف، تغيير الحالة، إعادة تعيين الحصص).
   - تحديث تسجيل الدخول `/api/auth/login` ليدعم حسابات الوكلاء تلقائياً والتحقق من حالة الحساب.
   - عزل استعلامات المستفيدين لضمان رؤية الوكيل لمستفيديه فقط.
   - التحقق من الحصة المتاحة عند إضافة مستفيد جديد عبر الوكيل.
   - تأمين حظر تعديل الحقول الخمسة المحمية على مستوى الخادم.

3. **الواجهة الأمامية (Frontend Implementation)**:
   - إضافة واجهة وتبويب "إدارة الوكلاء" في لوحة الأدمن.
   - تكييف لوحة التحكم لتدعم جلسة "الوكيل" مع إظهار الحصة وقفل الحقول الحساسة.
   - إضافة محرك البحث والفلترة الاحترافي المتعدد في قائمة المستفيدين.

4. **البناء والاختبار الشامل**:
   - بناء الكلاينت والسيرفر بنجاح والتأكد من خلوه من أي أخطاء lint.
   - اختبار تدفق الوكيل من البداية حتى النهاية.
